# Math — the five-step equation block, display and inline maths, numbered equations, theorem blocks, notation tables

Use on every page that states a result the reader must be able to implement: each key equation set goes through the five-step block (formulation → physical interpretation → engineering application → practical implementation → running-example instance), display equations the text refers back to are numbered and cross-referenced, results and definitions the reader will cite are theorem-like blocks, and the symbols a module introduces end in a notation table. Snippets: `math5.html`, `eq-numbered.html`, `theorem.html`, `notation.html`.

## Rules

- Engine: KaTeX auto-render (loaded from the CDN; maths needs internet). Display: `$$ … $$` or `\[ … \]`. Inline: **only** `\( … \)`. A single `$` is not a delimiter, so prices are safe — but `$$`/`$$$` cost classes are not: write "Low/Mid/High".
- Inside HTML, escape `<` as `&lt;` and `&` as `&amp;` (aligned environments: `a &amp;= b`).
- `<div class="eq">` wraps an overflowing display equation (long covariance or gain expressions) so it scrolls instead of breaking the layout; give it an id and it is numbered (below).
- **Five-step block — mandatory for every key equation set:** `<div class="math5">` with five `<div><h5>Label</h5>…</div>` children in the fixed order *Mathematical formulation · Physical interpretation · Engineering application · Practical implementation · Running-example instance*. The running-example numbers come from `00-overview.md` §1 verbatim, each derived number computed by the equations shown from stated inputs, and the equation set cited to its dossier source (evidence policy §5) — never an estimate.

**Use when** a result the reader must be able to implement. **Avoid** for one-line identities — write them inline.

## Numbered equations and cross-references — `eq-numbered.html` (E2), copy as LaTeX (C9)

Shape: `<div class="eq" id="eq-mercator">$$ … $$</div>`; refer to it with `<a class="eqref" href="#eq-mercator"></a>`. **Runtime** (`post`, after KaTeX rendered): every `div.eq[id]` gets a right-aligned `span.eq-num` "(n)", numbered in page order; `data-label="1a"` replaces the number without advancing the counter (so (1), (1a), (2)); an `a.eqref` with empty text receives "(n)" — author text is kept, a cross-page eqref keeps its text or shows its id; the box is numbered even when KaTeX did not load. `QC.eqLabel(id)` returns the label. Every display equation (`.katex-display`, or the `.eq` box when KaTeX is offline) shows a **Copy LaTeX** button on hover or focus; it copies the TeX source KaTeX keeps in its MathML annotation (fallback "Select & copy": a selected textarea with the source). **Rules:** ids start with `eq-`; one display equation per `.eq`; never type "(1)" by hand; a `.eq` without id stays unnumbered (the overflow wrapper only). **Use when** the text refers back to an equation. **Avoid** numbering every line of a derivation — number what is cited.

## Theorem, lemma, definition, example and proof blocks — `theorem.html` (B2)

Shape: `<div class="thm" data-kind="theorem" id="thm-mercator"><span class="thm-title">Mercator scale</span><p>…</p></div>`, kinds `theorem | lemma | proposition | corollary | definition | example | remark | proof`; the title span is optional. **Runtime** (`enhance`): theorem-like kinds (theorem, lemma, proposition, corollary, definition) share one counter per page, example and remark count on their own, the label "Theorem 2 (Mercator scale)" is injected as `span.thm-label` (the title span folds into it); a proof is unnumbered and becomes a collapsible `details.thm-proof` (summary "Proof", a closing ∎; `data-open` on the block opens it by default) that attaches visually to the numbered block directly above it; an `a.thmref[href="#thm-…"]` with empty text receives the label (a missing target shows the id in red). `QC.thmLabel(id)`. **Rules:** every numbered block has an id starting with `thm-`; a proof contains no other `.thm`; the statement is complete on its own (the proof may stay collapsed; print opens it). **Use when** a result, definition or worked example the reader will cite or implement. **Avoid** for one-sentence remarks that read fine as prose.

## Notation and constants tables — `notation.html` (E3)

Shape: `table.notation` with a `thead` Symbol | Meaning | Unit | Where defined and `td.sym` holding the symbol as inline maths (`\( \lambda \)`); `table.constants` with Constant | Symbol | Value | Unit | Source (`td.sym` again); a `caption` names the table, an id makes it a link target. `build_site_data.py` harvests every row (symbol as plain text, its TeX, meaning, unit, value, kind, page, the table id or the nearest `h2` as anchor, the Where/Source text) together with the optional hand-written `assets/notation.json` (`[{ "symbol", "tex"?, "meaning", "unit"?, "kind": "symbol"|"constant", "value"?, "page"?, "anchor"? }]`) into `DATA.notation = { entries, pages }`; `notation.html` (registry num `N`, group Reference, copied by `scaffold.py` like `glossary.html`) renders `div.notation-page[data-notation]` — A–Z jump bar, filter, kind select, sortable columns, a link to the defining page — and every entry joins the site search as kind Symbol or Constant. `QC.notation()` returns the entries. **Rules:** one meaning per symbol across the site (the validator warns on a conflict — rename the symbol or align the meaning with `SITE_PLAN.md` → Conventions); units as the conventions write them; values as the dossier quotes them, with the source. **Use when** a module introduces more than a few symbols or relies on constants. **Avoid** restating the glossary — a notation row is a symbol, not a term.

## Validator messages this module can trigger

`odd number of $$ (n)` — a price like `$$` or `$$$` will be rendered as maths · `\( n vs \) m` — unbalanced inline delimiters · `thm <id|#n> data-kind "x" unknown (theorem|lemma|…)` · `thm <id|#n> proof contains another thm block` · `thm <id|#n> (<kind>) has no id — it cannot be referenced` (warning) · `eq id "x" should start with eq-` (warning) · `notation table without thead` · `notation table row n without td.sym` · site-level, from `assets/notation.json`: `assets/notation.json must be a JSON array`, `notation entry n needs symbol and meaning: …`, `notation entry "x": kind must be symbol or constant (got …)`, `notation entry "x" points to missing page …` · site-level warning across pages and the json: `notation: symbol "λ" means "longitude" (m01-globe) and "wavelength" (m03-light)`.
