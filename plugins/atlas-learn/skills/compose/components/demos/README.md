# Demos — calculators, simulations and computed plots (the signature feature)

Use when a formula has ≥ 2 parameters the reader should *feel* (sizing, budgets, tuning, link budgets, filters); when an algorithm is best understood by running it (planners, schedulers, learning curves); when a design choice has a trade-off curve; when an input lives in the reader's own units or carries a tolerance. Snippets: `demo-calculator.html` + `demo-calculator.js` (controls → model → plot and readouts, with two named presets), `demo-plot.html` + `demo-plot.js` (a computed curve without controls), `demo-units.html` + `demo-units.js` (unit menus and an SI-prefixed field), `demo-uncertainty.html` + `demo-uncertainty.js` (tolerances → Monte Carlo, worst case, tornado).

## Shape

`.demo[id]` (optional `data-cite="#ref-…"`) > `.demo-head` (`h4` + `badge illustrative` reading "Model output") + `.demo-body` (`.demo-controls` with optional `.demo-presets` first, then `.ctl` rows — `label for`, `output for`, `input`/`select` — and `.demo-output` with a `canvas` and `.readouts` of `.readout` > `.r-label` + `.r-val`) + `.demo-note`. The `.js` file beside each snippet holds the body of the page's single `qc:ready` handler for that demo; paste it into the handler and rename the ids together with the markup. **Give every demo an id**: the URL state, presets, the link in the menu and the export file name need it (the validator warns otherwise).

## Runtime API

- `QC.bindControls(root, fn)` — fires once and on every input; `fn(v)` receives `{<input id>: value}` (ranges/numbers as floats **in the input's base unit**, checkboxes as booleans, selects as strings, `data-si` fields as the parsed number) and `output[for="<id>"]` elements are filled automatically (`data-decimals`, `data-unit`, the chosen display unit, `± n %` from `data-tol`). Controls the runtime injects (unit menus, the demo menu, presets) are never part of `v`. Returns the getter of the current values.
- `QC.plot(canvas, cfg)` — full reference incl. log axes, scatter/bars/error bars, second axis, heatmap and download in `plots/README.md`.
- `QC.fmt(v, decimals?)`, `QC.niceTicks`, `QC.onTheme(fn)`, `QC.isDark()`, `QC.store.get/set` (namespaced localStorage, safe when blocked), `QC.PAGES`, `QC.SITE`.
- Readout classes `good|warn|bad` on `.readout` colour the value. For custom drawings (top-down views, rotations, grids, Gantt) draw on your own canvas/SVG, read colours with `getComputedStyle(document.documentElement).getPropertyValue('--accent')` and re-render via `QC.onTheme`.
- **D1 state and presets** — `QC.applyPreset(demoId, name) → boolean` (false when the demo or preset does not exist), `QC.setDemoState(demoId, {id: value, …}) → boolean`, `QC.getDemoState(demoId) → {id: value}` (base units; `null` for an unknown demo), `QC.demoLink(demoId) → url` (the page URL with `#<id>?k=v&…`).
- **D2 export** — `QC.export(name, data, 'csv'|'json'|'md') → text` where `data` is `[[…], …]` (rows), `{columns, rows}`, `[{k: v}, …]` (objects, keys become columns) or `{sections: [{title, columns, rows}, …]}`; builds the text, downloads `<name>.<ext>` (through `QC.download` when another block provides it, else a Blob link) and returns the text.
- **D3 units** — `QC.units` (the conversion table below), `QC.convert(v, from, to)` (NaN for unknown units or different groups), `QC.fmtSI(v, unit, digits = 3) → "4.7 kΩ"`, `QC.parseSI("4.7k") → 4700` (prefixes `p n µ u m k M G T`, case-sensitive; any text after the prefix is the unit and is ignored, so a lone `m` is milli, not metres).
- **D4 uncertainty** — `QC.tolerancesOf(root) → {id: {nominal, tol}}` from every control carrying `data-tol` (percent → fraction, nominal in base units); `QC.mc(model, inputs, {n = 2000, seed = 1})` with `inputs = {k: {nominal, tol: 0.05} | {nominal, min, max} | {nominal, sigma}}` and `model(v) → number` returns `{nominal, mean, sd, p5, p50, p95, min, max, n, invalid, worst: {min: {value, inputs}, max: {value, inputs}}, tornado: [{name, low, high}]}` — seeded (mulberry32), uniform for `tol`/`min–max`, normal (Box–Muller) for `sigma`, `n ≤ 20 000`, the worst case from the `2^k` corners when `k ≤ 10` (±3σ for `sigma` inputs) else from the samples, the tornado one input at a time sorted by swing; `QC.tornado(el, tornado, {baseline, unit, digits})` draws an inline SVG (bars from the low-input result ↓ to the high-input result ↑ around the baseline, `t-lo`/`t-hi`/`d-text` classes, dark-mode safe).

## Demo state in the URL and named presets (D1)

Zero writer cost: every bound demo mirrors its inputs into the page URL as `#<demo id>?parts=9&partkb=40` (debounced, `history.replaceState`, never scrolls), and a page opened with such a hash restores the inputs before the first model run and scrolls to the demo — so a reader, a quiz or a teacher can link to a configured demo. Values are base units; checkboxes `1`/`0`; selects strings; numbers are clamped to the input's `min`/`max`.

Presets: `div.demo-presets` (first child of `.demo-controls`, or inside `.demo-head`) > `button[data-preset="over"][data-state="parts=9&partkb=40"]`. Clicking one sets the named inputs, runs the model once, writes the hash and marks the button `.active`; a manual change clears the mark; a hash or `setDemoState` that equals a preset lights it. Pairs are joined with `&` (write `&amp;` if your editor insists; both parse), names are input ids of that demo, missing inputs keep their value. The assessment module's predict-then-reveal block calls `QC.applyPreset` with these names.

## The demo menu: copy, export, link, sensitivity, reset (D2, D6)

Every `.demo` with a `.demo-head` gets a `⋯` button (`button.demo-menu-btn`, keyboard: Enter opens, ↑/↓ move, Esc closes) with: **Copy readouts** (`label: value` lines; shift-click gives a Markdown table), **Export CSV / JSON / Markdown** (every plotted canvas as a table `x, <series labels>` with one row per x, then the readouts, then the inputs; file `<demo id>.csv|json|md`), **Copy link** (D1), **Sensitivity ±10 %** (D6), **Reset** (every control back to its `value` attribute, presets unmarked, the sensitivity table removed). Clipboard failures fall back to a selected text box the reader copies by hand, like the code blocks' "Select & copy". `data-export="off"` on the demo hides the export entries, `data-sensitivity="off"` the sensitivity entry (e.g. for a simulation whose inputs are not continuous).

**Sensitivity ±10 %** perturbs every range/number input of the demo one at a time by −10 % and +10 % (clamped to `min`/`max`, snapped to `step`; an input already at a bound shows `—`; a zero value moves by 10 % of its range), dispatches `input`, reads every `.readout .r-val` as displayed (first number in the text) and restores the original values and outputs — even when a handler throws. It then renders `table.sensitivity` under the readouts: one row per input, per numeric readout the Δ at −10 %, the Δ at +10 % and the elasticity (Δout/out)/(Δin/in) averaged over both sides, the largest |elasticity| per readout highlighted; a × closes it. Readouts without a number (verdicts) are skipped; a model that debounces its work shows no change, so keep demo models synchronous (authoring rule).

## Unit-aware inputs (D3)

`input[type=range|number][data-unit-group="length"][data-unit="km"]` — `data-unit` is the **base unit the markup is written in** (`min`, `max`, `step`, `value` and the model's `v` stay in it); the runtime adds `select.unit-select` beside the output listing the group's units. Choosing one converts the slider and its label to that unit (affine °C/°F/K included); the model keeps receiving the base unit, so page code never changes. The choice applies to every input of that group on the page and is remembered under `compute:unit:<group>`.

Groups and units: length `m cm mm km in ft mi` · mass `kg g lb oz` · time `s ms min h` · temperature `K °C °F` · speed `m/s km/h mph kn` · pressure `Pa kPa bar psi atm` · energy `J kJ Wh kWh cal` · power `W kW hp` (mechanical) · angle `rad deg` · frequency `Hz kHz MHz rpm` · voltage `V mV kV` · current `A mA` · data `B KB MB GB` (decimal). A unit outside the table is a validator error; a quantity outside the groups keeps the plain `data-unit` label.

`input[type=text][data-si]` accepts a prefixed number (`2.2µ`, `4.7k`, `1M`); `v` holds the parsed value, the output shows `fmtSI(value, data-unit)` and the field is marked `.si-invalid` while it does not parse. Use `type="text"` (a number input rejects letters — the validator warns).

## Uncertainty and tolerances (D4)

Put `data-tol="5"` (percent, 0..100) on the inputs that carry a tolerance; the output label shows `± 5 %`. In the handler, `QC.tolerancesOf('#demo-id')` turns them into the `inputs` object, `QC.mc(model, inputs, {n, seed})` runs the model (the same function you use for the nominal readouts, called with `{id: value}`) and `QC.tornado(el, r.tornado, {baseline: r.nominal, unit})` draws the chart into a `div.tornado`. Say in `.demo-note` which distribution the band means (uniform here; use `{nominal, sigma}` for Gaussian inputs) and that the seed makes the run repeatable. Keep `n` on a select so the reader can trade speed for smoothness; 20 000 is the cap.

## Rules

**Evidence first (evidence policy §5):** a demo implements one documented calculation — the page block names its `C` id — and cites it in the `.demo-note` (`a.cite`) or with `data-cite` on the `.demo`; the validator fails a demo that cites nothing (`demo <id> cites no source for its model`). No documented method, no demo: the section gets a table or cited text. Default inputs come from the parameter sheet, slider ranges stay inside the documented validity range, and nothing the reader did not enter or the source did not state feeds the model. State what the method does not model in `.demo-note`, as the source states it; the head badge `illustrative` reads "Model output"; guard NaN and instability and cap loop counts; no blocking work on input events; keep the model synchronous (the sensitivity view and the export read the readouts right after each input event); no external libraries (if unavoidable, cdnjs/jsdelivr with an exact pinned version); never claim precision the model lacks. Input ids are the keys of `v` and must be unique on the page — rename them when a page has two demos; preset `data-state` names them. Readouts carry units in the `.r-val` text (the export and the copy take the text as shown). Every `.demo` counts in the trust footer's "interactive demos · documented models" line.

**Use when** a formula with ≥ 2 parameters, an algorithm to run, a trade-off curve, an input in the reader's units, a result with a tolerance. **Avoid** a demo whose output the reader cannot check against a number in the text, plots of constants, and any model the dossier does not document.

## Validator messages this module can trigger

`<output for="x"> has no input` · inline-script syntax errors (node) · `odd number of $$` / `\( vs \)` from maths in the note · `preset "over" names unknown input "foo"` · `preset "over" defined twice in demo-budget` · `preset "over" has no data-state` · `unit group "volume" unknown` · `unit "yd" is not in group length` · `unit input "x" has no data-unit` · `unit input "x" must be type range or number` · `data-tol "abc" must be a number 0..100` · warnings: `demo without id (no URL state, presets, link or export)` · `unit input "x" has no output[for] (the unit menu sits beside it)` · `data-si input "x" should be type text so a prefix like 2.2µ can be typed`.
