# Diagrams — inline SVG, and step-through build-ups

Use for architecture, signal/control/power flow, state machines, pipelines, stacks and timelines with geometry; use the step-through variant when a mechanism is best understood one layer at a time (a filter cycle, a protocol exchange, a derivation), and the exploded-view variant when the reader should switch layers of one drawing on and off. Every diagram can be downloaded as SVG or PNG. Snippets: `diagram.html`, `diagram-steps.html`, `diagram-layers.html`.

## Rules (both snippets)

- **Evidence (evidence policy §6, §7):** every box is a documented component and every line, arrow, group and layer a documented relationship (the dossier's `R` rows or a cited fact) — never one inferred because it seems plausible. Cite on the figure, `figure.diagram[data-cite="#ref-a, #ref-b"]` (the runtime adds a "Sources: [n]" line to the caption), and on the elements where they rest on different sources (`<rect … data-cite="#ref-a">`, `<g data-cite=…>`, `<path data-cite=…>`): the reader hovers or focuses an element to see its source and clicks to open it, and a drag that pans a zoomed diagram does not count as a click. The validator fails a diagram that cites nothing and a `data-cite` that does not resolve; the registry site map (`svg[data-sitemap]`) and the concept map are exempt.
- `figure.diagram` > `svg[viewBox]` with `role="img"` and `aria-labelledby` pointing at a `<title id>`, then `figcaption` (bold "Figure n.m — Title." + what to notice) and a `.legend` with only the entries the drawing uses.
- Boxes: `d-box` + `alt | accent | mcu | pwr | ctl | rf | mech | ai`; dashed group outline `d-group`.
- Lines: `d-line` + `d-data d-ctrl d-power d-rf d-mech` (+ `d-dash`); arrowheads `url(#arr | #arr-data | #arr-ctrl | #arr-power | #arr-muted | #arr-accent)` are defined globally by the runtime.
- Text: `d-text` + `sm | xs | b | lbl | mono`; fills `d-fill-data|ctrl|power|ink|muted|accent|surface`.
- **Never hard-code colours** (`fill="#fff"`) — classes make dark mode work. Text ≥ 10 px at viewBox scale; check coordinates so labels never overlap; wrap clickable blocks in `<a href="page.html">`.
- Zoom (+/−, Ctrl/⌘+scroll), pan (drag when zoomed), fullscreen and a caption hint are added automatically; `data-nozoom` on the figure opts out (e.g. a JS-driven diagram that manages its own viewBox).
- `<svg data-sitemap>` inside a `figure.diagram` renders the registry as a clickable group map — see `overview/widgets.html`.

**Use when** architecture, signal/control/power flow, state machines, pipelines, stacks, timelines with geometry. **Avoid** a diagram that restates a bulleted list.

## Step-through — `diagram-steps.html`

`figure.diagram[data-steps]`: the base elements are always visible; each `<g data-step="n">` layer appears from step n on; `ol.diagram-steps` holds one caption per step (shown one at a time). The runtime adds Prev / "Step k of n" / Next / All controls under the drawing and ← → keys when the figure is focused. **Use when** a build-up explains better than the finished picture: the predict/update cycle, a message exchange, a derivation that adds one term per step. **Avoid** steps that only move the eye — every layer must add a new element.

## Download — SVG and PNG (C9)

Nothing to write: every `figure.diagram` that has the zoom tools also gets a `⤓` button opening a two-entry menu, **SVG** and **PNG (2×)**. The SVG is a standalone file: the runtime clones the drawing, inlines the computed `fill`, `stroke`, `stroke-width`, `stroke-dasharray`, `font-family`, `font-size`, `font-weight`, `letter-spacing`, `opacity` … of every element (so the `d-*` classes survive outside the page), copies the `#arr-*` arrowheads and any other `url(#id)` target into `<defs>`, sets `width`/`height` from the viewBox and puts a background rect in the current theme's surface colour under the drawing (white in light mode; export in dark mode gives a dark picture with light ink). The PNG is that SVG drawn on a canvas at 2× the device pixel ratio (long side capped at 8192 px); when the browser refuses (a tainted canvas, an external image inside the SVG) the SVG is saved instead. The file is named after the figure id (`fig-research-stage.svg`). Hidden step layers and switched-off layers are hidden in the export too — the reader downloads what the page shows; the viewBox is always the full drawing, whatever the zoom. Page scripts and other features reuse the helpers: `QC.download(filename, data, mime)` (string, ArrayBuffer or Blob → anchor click; returns `true` when the click was dispatched) and `QC.svgToString(svg, { viewBox, background })` (the standalone SVG text; `background: null` omits the rect). **Rules for writers:** keep text as `<text>` (never rasterised), keep colours in `d-*` classes (a hard-coded `fill` is exported as is and breaks in dark mode), and give the figure an id — it becomes the file name.

## Exploded view — `diagram-layers.html` (C11)

`figure.diagram[data-layers]` whose SVG holds `<g data-layer="Name">` groups, one per layer the reader may switch (two or more; several groups may share a name and switch together); `data-layer-off` on a group hides that layer at first. The base drawing outside the groups is always visible. The runtime adds `div.layer-tools` under the drawing (after the step tools when the figure also has `data-steps`): one checkbox chip per distinct name plus **All** and **None**; a hidden layer gets `.layer-hidden` (`display: none`), so a download shows the current selection; print shows every layer. **Use when** one picture stacks several concerns — the layers of a device, a stack, a page's chrome against its content, an overlay of measured against modelled — and seeing one without the others explains something. **Avoid** layers that are just categories of boxes with nothing to learn from hiding them, and a layer name used for two unrelated groups.

## Validator messages this module can trigger

`n hard-coded SVG colour(s) — use d-* classes so dark mode works` · `step diagram <id> has fewer than 2 data-step layers` · `step diagram <id>: n captions for m steps` (the caption count must equal the number of distinct steps) · `exploded view <id> has fewer than 2 layers` (`data-layers` needs ≥ 2 distinct `g[data-layer]` names) · `layer "Frame" used twice in <id>` (a name may appear once; use one group per layer) · `layer without a name in <id>` (`data-layer=""`). Advice (warning): `figure <id> has g[data-layer] groups but no data-layers (no layer toggles)`. C9 has no markup and no validator message.
