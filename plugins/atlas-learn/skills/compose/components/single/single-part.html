01 · Why atlas-learn splits the work

One prompt that says “research this and write me a guide” asks a single context to find sources, judge them, structure a curriculum and write every page. atlas-learn gives each of those jobs to a separate agent with its own context, and puts a file between every pair, so each step can be checked and repeated on its own.

Four files, four questions

The insight answers what do you want; the brief answers what will be covered; the dossier answers what is true, and who says so; the site answers how is it explained. A later stage may read an earlier file but never rewrites it.

Paths, not contents

The main agent hands each subagent file paths and reads back one RESULT line. The research never passes through its context, which stays short across a long topic, and long contexts are where models lose track of what sits in the middle [2].

Running example

The map-projections topic: six modules, researched by three agents in parallel and written by four page writers. When session 2 ended after M03, session 3 dispatched only M04 and M05 [4].

Pitfalls
  • Pasting a dossier into the main conversation “to check it” → the main agent's context fills → open the file in the editor instead.
  • Editing INSIGHTS.md after the brief was written → the insight hash no longer matches → run /atlas-learn:research <slug> again to rewrite the brief.
