About the examples

Every snippet describes atlas-learn itself, and the map-projections sample topic from the plugin README stands in for a real run; where a component needs outside material (a photo, a 3D model), it comes from cartography, the field atlas-learn is named after. Figures and demos about atlas-learn cite its documentation [4]; the domain examples (map projections, SPI, TLS, an AVR pinout) cite a template placeholder [5] instead of a source nobody retrieved — in a site, every cite names a dossier entry (references/evidence-policy.md). When a page writer copies a snippet, every word of it is replaced with the topic's own content; only the markup stays. The rules are in references/authoring-rules.md.

How an atlas-learn site is put together

A site is index.html at the topic root, every other page under pages/, and assets/. Two asset files are fixed code copied from the template and never edited per site; two are data written per site. The runtime reads the registry (assets/site.js) to build the sidebar, search index, pager, progress and the overview widgets, so the registry is written first and page file names never change afterwards.

core/callout.html

Use when: a short aside the reader must not skim past — one variant per purpose (note, tip, warn, safety, case, research, mistakes); never more than two in a row. Replace: keep only the variant you need; title and text. Runtime: none. Validator: none.

Convention

Paths are relative to the topic folder topics/<slug>/. Everything under tmp/ is a working file: ignored by git, never cleared by the plugin.

Rule of thumb

Approve the brief only when every module names a deliverable you could check. A module without one becomes a page without one.

Limitation

The gates check structure, links, anchors and script syntax. They never open the site in a browser, so a diagram with overlapping labels still passes.

Guardrail

Never give a page writer web tools to save a research round. Two producers of one fact is how a site ends up contradicting itself; a missing fact goes back to a researcher as a gap.

Running example

The map-projections topic: six modules and a project over three sessions. Session 2 ended after M03 was researched; the next /atlas-learn:go dispatched only M04 and M05 [4].

Open question

Whether a fresh-eyes brief reviewer finds more defects than a second pass by the author has not been measured on atlas-learn runs.

Mistakes to avoid
  • Editing assets/site.js by hand: it is generated. Edit site.json, then run scaffold.py --sync.
  • Renaming a page file after the writers started: every cross-link to it breaks.

import math

R = 6371.0088                                   # mean Earth radius in km (the sphere every module assumes)
CITIES = {"Hanoi": (21.03, 105.85), "Nuuk": (64.18, -51.72)}

def mercator(lat_deg, lon_deg, lon0_deg=0.0):
    """Spherical Mercator forward equations: x = R (lambda - lambda0), y = R ln tan(pi/4 + phi/2)."""
    lat, dlon = math.radians(lat_deg), math.radians(lon_deg - lon0_deg)
    return R * dlon, R * math.log(math.tan(math.pi / 4 + lat / 2))

for name, (lat, lon) in CITIES.items():
    x, y = mercator(lat, lon)
    k = 1 / math.cos(math.radians(lat))         # scale factor sec(phi): lengths grow by k, areas by k squared
    print(f"{name:<6} x = {x:8.1f} km   y = {y:7.1f} km   k = {k:.3f}   area x {k * k:.2f}")

import re
import subprocess

def run_gate(script, *args):
    """Run an atlas-learn gate script and return its RESULT fields (example, not the plugin's own code)."""
    proc = subprocess.run(["python", script, *args], capture_output=True, text=True)
    lines = [l for l in proc.stdout.splitlines() if l.startswith("RESULT:")]
    if not lines:                                   # no RESULT line: treat it as a failed gate
        return {"status": "FAIL", "exit": proc.returncode}
    fields = dict(re.findall(r"(\w+)=(\S+)", lines[-1]))
    fields["exit"] = proc.returncode                # 1 on FAIL, 0 on PASS
    return fields                                   # flip the plan row only when status == "PASS"

Why a page has a size budget

A module page of 70–160 KB reads in one sitting and still validates in seconds; the priority module may grow to 250 KB because the brief spends most of its depth there. A single-page guide keeps the whole topic under about 250 KB so it opens from a file share without a server. The strip under this heading says what to read first (the glossary's term table and the trust footer), what pairs with it (the single-page frame), how long it takes and when it was last checked.

Writers set these attributes on the h2 only; the runtime builds the strip, resolves the titles from the registry and hides a reading time under 120 words unless data-time says otherwise.

Scale factor

The scale factor of a projection at a point is the ratio of a distance on the map to the corresponding distance on the globe, taken in the limit of small distances; it depends on the point and, for most projections, on the direction.

Mercator scale

On the Mercator projection the scale factor is the same in every direction and equals \( k = \sec\varphi \) at latitude \( \varphi \); the map is conformal, and no finite sheet reaches the poles.

Conformality forces the north–south stretch to equal the east–west stretch. A parallel at latitude \( \varphi \) is \( 2\pi R\cos\varphi \) long on the globe but \( 2\pi R \) long on the map, so the east–west factor is \( 1/\cos\varphi = \sec\varphi \). Integrating the same factor along a meridian gives \( y = R\ln\tan(\pi/4 + \varphi/2) \), which diverges as \( \varphi \to \pi/2 \).

At Greenland's latitude of about 72° the Mercator scale factor is \( \sec 72^\circ \approx 3.2 \), so areas are inflated by \( k^2 \approx 10 \) — which is why the island looks as large as Africa on a web map.

Tissot's indicatrix draws \( k \) in every direction as an ellipse: a circle means conformal, a constant area means equal-area; no projection manages both.

const budgetCanvas = document.getElementById('demo-budget-canvas');
const budgetEl = id => document.getElementById(id);
QC.bindControls('#demo-budget', v => {
  const n = Math.max(1, Math.round(v.parts)), s = v.partkb, B = v.budget, F = v.frame;
  const total = F + n * s, allow = (B - F) / n;
  const line = [], maxN = 16;

01 · Why atlas-learn splits the work

One prompt that says “research this and write me a guide” asks a single context to find sources, judge them, structure a curriculum and write every page. atlas-learn gives each of those jobs to a separate agent with its own context, and puts a file between every pair, so each step can be checked and repeated on its own.

Four files, four questions

The insight answers what do you want; the brief answers what will be covered; the dossier answers what is true, and who says so; the site answers how is it explained. A later stage may read an earlier file but never rewrites it.

Paths, not contents

The main agent hands each subagent file paths and reads back one RESULT line. The research never passes through its context, which stays short across a long topic, and long contexts are where models lose track of what sits in the middle [2].

Running example

The map-projections topic: six modules, researched by three agents in parallel and written by four page writers. When session 2 ended after M03, session 3 dispatched only M04 and M05 [4].

Pitfalls
  • Pasting a dossier into the main conversation “to check it” → the main agent's context fills → open the file in the editor instead.
  • Editing INSIGHTS.md after the brief was written → the insight hash no longer matches → run /atlas-learn:research <slug> again to rewrite the brief.

Go deeper: [1] for how subagents work, [3] for the orchestrator–workers pattern.

  <p>The insight answers <i>what do you want</i>; the brief answers <i>what will be covered</i>; the dossier answers <i>what is true, and who says so</i>; the site answers <i>how is it explained</i>. A later stage may read an earlier file but never rewrites it.</p>
  <h3 id="m01-paths">Paths, not contents</h3>
  <p>The main agent hands each subagent file paths and reads back one RESULT line. The research never passes through its context, which stays short across a long topic, and long contexts are where models lose track of what sits in the middle <a class="cite" href="#ref-liu2023">[2]</a>.</p>
  <div class="callout case"><span class="callout-title">Running example</span><p>The <code>map-projections</code> topic: six modules, researched by three agents in parallel and written by four page writers. When session 2 ended after M03, session 3 dispatched only M04 and M05 <a class="cite" href="#ref-atlas-learn-docs">[4]</a>.</p></div>
