# Component catalog — index

Read this file and the README of every module in your MODULES list; open a snippet when you use it. A component you need that is not on your list: find it here, read its README, report the extra load in a Friction line.

Every class the snippets use already exists in `template/assets/style.css`; every behaviour in `template/assets/app.js` (both copied verbatim into every site). Pages add **no CSS and no framework** — they use these building blocks, and page-specific JavaScript lives in the page's single `qc:ready` handler. Each snippet is a complete working fragment with example values: copy it, then change what its first-line header comment names under `replace:`. Every figure and demo snippet cites its evidence (`data-cite`); in the catalog the examples about atlaspedia cite `#ref-atlaspedia-docs` and the domain examples cite the template placeholder `#ref-placeholder` — in a site every cite names a dossier entry, and nothing in a snippet is evidence (`references/evidence-policy.md`). `template/styleguide.html` renders every snippet once in the real stylesheet and runtime; it is generated from this catalog by `python <PLUGIN_ROOT>/scripts/check_components.py --styleguide`, never edited by hand.

Maintainers (not writers): a new component is one snippet here (header comment first line, unique ids, no maths delimiters such as `$$` or `\(` inside the header text — it is rendered as prose in the style guide), one block in `style.css`/`app.js`, one `validate.py` check, one row in this table, one line in the compose skill's derivation table, then `check_components.py --styleguide` until it passes.
